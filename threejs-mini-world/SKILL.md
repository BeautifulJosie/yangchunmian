# 3D 微缩小世界 生成指南

这份 SKILL.md 和 `template/` 配套使用。`template/` 是一份**已经做完的参考实现**（加州落日小岛 LA Daydream），
不是让你原样交付的成品：照着它的结构和做法，按用户的主题重做一座新的小世界。
**改的是主题和内容，不是做法**——底座、光照、水面、角色系统、音乐、截图自检这些套路直接复用。

做完是一个 Vite + TypeScript + three.js 的静态网页，`npm run build` 后丢到任何静态托管就能打开。

## 安装好之后：尽量少让用户操作

用这个 Skill 的多半不是程序员：

- 能自己运行的命令就自己运行；需要用户点「允许」时，用一句大白话说明这一步在做什么。
- 遇到解决不了的问题，直接说清楚卡在哪、给一个简单的手动办法，不要在一个办法上反复死磕。
- 安装完在同一个对话里接着往下走，告诉用户「3D 小世界工具装好了」，然后进入第 0 节。
  示例开场白：
  > 3D 小世界工具装好啦！先告诉我你想做一个什么主题的小世界，再发 2~3 张你喜欢的参考图，
  > 我们先聊范围和风格，聊定了我再动手。

## 工作原则（整个过程都适用）

1. **先讨论，再动手。** 用户一上来说「帮我做个小岛」时，先出范围清单和推荐，不要直接写代码。
2. **先看样张，再定风格。** 风格样张必须是**真实的 three.js 渲染**，不要画平面草图。
   参考实现里一开始给用户画了 5 张平面 2D 风格图，用户明确说「不喜欢平面的」，浪费了一轮。
3. **每改一次都渲染一次，自己先看。** 用无头浏览器截图（见第 5 节），看完再给用户，不要把没看过的东西发出去。
4. **用户的反馈会带截图和红框。** 这是最准的反馈方式，按图改，别凭文字猜。
5. **如实汇报。** 做了什么、没验证什么（比如音乐你听不到、手机没真机测）都要直接说，不要说「已完美」。
6. **先定一个标准场景，再衍生。** 先把一个光照/时间的场景做到定稿，夜晚、四季之后基于它改，不要一开始就铺开做多套。

## 0. 开始前，先问清楚

- 主题是什么（海边小镇？雨夜便利店？校园？），**至少一张参考图**。
- 想要哪些氛围：光照（白天/日落/夜晚）、季节、背景音乐、动态元素。
- 是否要做成「可拖放贴纸」玩法（素材栏 + 空岛），还是只做一座摆好的岛。
- 之后是否要发小红书/做海报。

资料不全不用等，缺的先按推荐做，之后随时回填。

## 1. 讨论范围：做什么 / 不做什么

给出一份清单让用户确认，并给出你的推荐。参考实现当时定下的范围：

**做**：一块方形海洋底座 + 一座小岛；一套主题建筑和小物；二十来个小人，各自做一件事；
一种标准光照（日落）；水面；会动的元素（摩天轮、过山车、小飞机、海鸥）；背景音乐；鼠标 + 键盘控制视角。

**不做（第一版）**：多人/账号/云存储、AI 生成模型（用代码几何体搭，风格统一、没有加载时间）、室内视角、
手机端拖放、插画级的细节。

岛的默认状态建议**摆满**（第一眼就好看），再配「一键清空」。

## 2. 定风格：先渲染样张

做 3~5 个视觉方向，**每个都用真实 three.js 小场景渲染**，同一个视角、同一个时间，只换画法，
这样用户比较的是风格本身。给出你的推荐和每个方向的风险。

> 底座的经验：参考图里的岛通常是「薄薄一片地质切片 + 大面积水 + 岛体积感强」。
> 第一版把地质层做得太厚，用户说「占画面太多、不精致」，后来改薄并把岛放大、素材整体缩小，立刻好看很多。

## 3. 搭场景（照着 `template/src/` 的结构）

| 文件 | 作用 |
| --- | --- |
| `palette/index.ts` | 颜色 token，所有物件从这里取色 |
| `scene/helpers.ts` | 材质缓存、盒子/圆柱/球等小工具、文字招牌（canvas 贴图） |
| `scene/base.ts` | 海洋底座（分层岩石）、岛的地形、**`groundHeight()` 地形高度查询** |
| `scene/water.ts` | 水面 shader：涌浪 + 细波纹 + 阳光碎银 + 岸边浅滩/泡沫 |
| `scene/sky.ts` | 天空穹顶 + 太阳 + 光照预设（`SkyLook`），以后加夜晚/季节就是再加预设 |
| `scene/props.ts` | 所有建筑和小物（每个是一个返回 `THREE.Group` 的函数） |
| `scene/figures.ts` | 小人的参数化生成（风格、配色、帽子、姿势）+ 人和载具一体的组件 |
| `scene/characters.ts` | **角色贴纸目录**：每个角色 = 人 + 道具 + 动作，带 `id / name / build() / animate()` |
| `scene/island.ts` | 默认布置：把所有东西摆上岛，并按地形自动落地 |
| `audio/music.ts` | 程序化配乐（Web Audio），在线播放和离线渲染共用同一份代码 |
| `cameraKeys.ts` | 键盘调视角（A/D 环绕、W/S 俯仰、Q/E 远近），速度是文件顶部三个常量 |

要点：

- **所有物件都用「地形高度查询」落地**，不要手写 y 坐标，否则会悬空或埋进地里。
  需要放在结构上的（阳台、桥面）单独给 `lift`。
- 整套素材用一个统一的缩放系数（`PROP_SCALE`）缩小，岛才有「模型感」。
- 描边/低多边形/柔光的取舍见第 2 节样张；参考实现用的是低多边形 + 平滑小人 + 柔和阴影 + 轻微泛光。

## 4. 小人和角色（最容易出问题的部分）

参考实现里小人返工最多，经验都在这：

1. **先选小人风格再大批量做。** 渲染 4 种比例（糖豆 / 大头娃 / 圆润 / 木偶）让用户挑，
   后面所有人物都按选中的做。最后用户选的是「木偶」：圆柱身 + 圆头 + 点状眼睛和腮红。
2. **一体化。** 头和身体分开的几何体光照一打就露馅，用一个连续的身体；
   骑车、滑板、冲浪做成**人 + 载具一个组件**，一起移动。
3. **穿模是头号敌人。** 木偶没有腿时，骑自行车一定穿模——**改成「推着自行车走」**比硬骑靠谱。
   需要坐姿的，给一对短腿（`legStubs`）。
4. **每个人要有「在做什么」。** 只说「站着」会呆。给每个角色一件道具和一个动作：
   举着菜单的服务员、捧着冰淇淋的人、举着橙色马天尼的人、靠在一起的情侣（头顶一颗会跳的小心）。
5. **先出「角色总表」再放回场景。** 把每个角色单独渲染一张、拼成一张联系表，用户逐个挑毛病，
   确认后再放回岛上。放回去时按「区域」分开摆，避免互相穿模和悬空。
6. **放回场景后逐个近景检查。** 用默认视角方向对每个角色拉近渲染一次（见 `scripts/shoot-characters.mjs`
   和 `references/lessons.md`），挨个看有没有穿模、悬空、背对镜头。

## 5. 无头浏览器渲染自检

这是整个流程的核心工具：**每次改动后自己先看一眼**。

```bash
npm install
npm run dev                         # 另开一个终端或后台跑，默认 http://localhost:5173
node scripts/shoot.mjs shots        # 渲染 3 个全景角度到 shots/
node scripts/shoot-characters.mjs   # 角色逐个渲染（?test=characters）
node scripts/shoot-styles.mjs       # 小人风格对比（?test=figures&style=...）
```

- 脚本用 Playwright + Chromium + SwiftShader 软件渲染，不需要显卡。
  找不到浏览器时设置 `CHROMIUM_PATH=/path/to/chrome`。
- 页面暴露了一个 `window.__island` 钩子（设置相机、推进动画时间、渲染并导出 PNG），脚本全靠它。
  URL 加 `?shot=1` 会跳过「点击进入」遮罩。
- 一次只截你关心的东西；全景看整体，近景看细节，**别指望一张图看完所有问题**。
- 常见陷阱：水面和下面的方块 **z-fighting**（让下面的方块顶面低于水面）、物件被阴影相机裁掉
  （放大阴影相机范围）、dev server 在多轮对话之间被回收（脚本报 `ERR_CONNECTION_REFUSED` 就重启它）。

## 6. 光照、水面和天空

- 参考实现只做**一种标准光照：加州日落**（橙红到橘黄再到紫的天空 + 带光晕的太阳 + 碎银水面）。
  夜晚、四季之后基于同一套代码加预设（`SkyLook`），亮灯的物件用 `lamp()` 材质标记，夜晚统一点亮。
- 天空是一个渐变穹顶 shader；**太阳圆盘的位置只为画面服务**，不必和光线方向严格一致。
- 水面用 shader，不用 three.js 自带的 Water：自己控制浅滩、泡沫和高光，颜色也能按预设换。
- 轻微泛光（Bloom）能让太阳、招牌、灯串有「晕开」的感觉，强度别开大。

## 7. 动态元素

挂在场景里就跑，由 `animateIsland()` 每帧驱动：摩天轮转、过山车小车沿样条轨道跑、小飞机拉横幅绕圈、
海鸥扇翅膀、面包车沿马路开、冲浪的人随浪起伏、火烈鸟漂浮、泡泡上升。
角色自己的动画写在 `characters.ts` 的 `animate()` 里，放回岛上时自动接上。

## 8. 背景音乐

用 **Web Audio 实时合成**，不依赖任何音频文件，没有版权问题，仓库很小：

- 底层：粉红噪声过滤成海浪、很轻的风、偶尔的海鸥。
- 上层：慢速 lo-fi（电钢琴和弦 + 五声音阶拨弦旋律 + 低音 + 轻鼓和刷子），循环进行。
- 浏览器要求用户先点一下才能出声，所以做一个「点击进入」遮罩 + 右下角静音按钮。
- **在线循环**用一个小节游标连续往前排（别用时间差取整，会重复或跳小节，参考实现踩过）。
- **离线试听**用 `OfflineAudioContext` 渲染成 WAV（`scripts/render-music.mjs`），让用户先听，满意再放进页面。
- **你自己听不到。** 能做的只有检查没报错、没削波；好不好听要用户来判断，并如实说明。

## 9. 视角控制

- 鼠标：`OrbitControls`（拖动旋转、滚轮缩放）。
- 键盘：A/D 环绕、W/S 俯仰、Q/E 远近，和鼠标可同时用。
  这是为之后「拖贴纸时鼠标被占用」准备的。用户嫌快就降低 `cameraKeys.ts` 顶部的三个常量。

## 10. 发布

- `npm run build` 得到 `dist/`，任何静态托管都行（Cloudflare Workers/Pages、GitHub Pages 等）。
- 画布文字用了 Google Fonts（Oswald / Nunito），页面里要加字体链接，并在建场景前等字体加载完
  （`main.ts` 里已有）。托管在有内容安全策略的环境时，注意外部字体和脚本的白名单。
- 把 `.js` 单独当文件发布时，HTML 里用相对路径引用。

## 11. 小红书海报（可选）

`template/poster/` 里有 4 张 3:4 海报的 HTML 模板：

1. **总览图**：干净的全景 + 左上标题 + 底部手绘风线稿（SVG）和一句话说明。
2. **细节图**：每张 2~3 张细节截图，配手写体小注释和箭头，像手帐。

```bash
node scripts/shoot-poster-shots.mjs   # 渲染总览和各细节镜头到 poster/
node scripts/make-posters.mjs         # 把 p1~p4.html 合成 2160x2880 的 PNG
```

镜头位置和文案都是这座岛专用的，换主题要改 `shoot-poster-shots.mjs` 里的镜头列表和 `p*.html` 的文字。
细节镜头的取景要自己看：近了会只剩一个物件，远了又看不清，**每张都要看过再合成**。

## 12. 还没做的（诚实说明）

参考实现**没有**做：夜晚/季节预设、素材栏 + 拖放布置（预制位吸附）、保存/分享。
这些在设计上已经讨论过（固定位置吸附，不做自由放置，避免「过山车乘客被放到沙滩上」这类语义错位），
`characters.ts` 的目录结构就是为它准备的。用户如果要做，从这里接着往下做。
